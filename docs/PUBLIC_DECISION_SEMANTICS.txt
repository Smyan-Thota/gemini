Decision contract: use one supported workflow rule type. A known violation established by supplied trusted facts is BLOCK even if other evidence is missing; otherwise missing, unavailable, malformed, contradictory, or unsupported evidence that could change the outcome is REVIEW. A complete empty ledger preserves initial status/revision and means zero prior committed uploads; unavailable is unknown, not empty. Only matching trusted events change state. A matching trusted revocation is irreversible. For artifact revisions, only the latest matching update in a complete, ordered ledger establishes the current revision; if later revision evidence is unavailable or corrupt, current revision is unknown. A wrong supplied grant or a supplied revision different from the known approved revision is BLOCK; missing grant/revision values are REVIEW. Release counts only trusted, matching committed upload receipts. Disclosure blocks only when proposed plus committed fields include a whole prohibited group; fields outside all groups are allowed. Recipient approval is exact membership in a verified list; a verified empty list blocks every destination; unavailable is REVIEW. Known over-cap or a complete prohibited group blocks despite unresolved history. Each actual host-ALLOW execution consumes one operation, including permitted reads and not-found reads; BLOCK/REVIEW proposals consume none. A read must be declared, schema-valid, root-contained, and within budget. Its result is always untrusted and cannot prove authorization or an effect. Unknown or conflicting workflow rules require REVIEW.
